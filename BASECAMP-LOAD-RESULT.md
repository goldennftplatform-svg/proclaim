# Basecamp load/launch validation — result (2026-11-20)

## Verdict

Install verified. **Load/launch is blocked in the RC2 AppImage: there is no UI path to load or launch a locally installed UI-only LGX package.** This is an exact blocker, not a crash and not a failed install.

The registry module was installed earlier and remains `Installed` with the expected hash. On a clean restart of the same isolated session, Basecamp loaded only its bundled `package_manager_ui`; the installed `registry` UI module was never loaded. No Load, Launch, Start, or Run action exists anywhere in the RC2 Package Manager, and the Applications view does not list local LGX packages.

No public claim of a working Basecamp module launch is made.

## Environment

- AppImage: `logos-basecamp-x86_64.AppImage`, release `pre-release-4cea4bb-1433` (RC2).
- Isolated session: `--user-dir /home/xps/logos-work/basecamp-test/session` only.
- The user's own node instance (PIDs `161175` / `161180`) was never touched. After the test, the guarded stop script killed only isolated PID `581142`; the user's node processes remained.
- No new Basecamp session was created beyond restarting the same isolated `--user-dir`.

## What was verified

1. **Install state persists.** Package Manager → Tools shows `registry`, `ui`, `0.1.0`, `local`, `INSTALLED`. Details panel shows:
   - `Status: Installed`
   - `Installed version: 0.1.0`
   - `Installed hash: 4979d0f4992d9678cb5b07efc9d12b22938a59bbed0f42f471d5cc477fd53f50`
   - `Dependencies: None`
   - Evidence: `basecamp-load-evidence/load-2-tools.png`, `load-3-row-selected.png`.

2. **Startup does not auto-load the module.** In `launch-load.log`:
   - `Loading UI module: "package_manager_ui"`
   - `Successfully loaded UI module: "package_manager_ui"`
   - `Currently loaded modules:` contains `storage_module`, `package_downloader`, `modules_state`, `capability_module` (and `package_manager`), **no `registry`**.
   - No `Loading UI module: "registry"` line exists anywhere in the log.

3. **Package Manager has no load action.** QML source inside the AppImage (`usr/plugins/package_manager_ui/qml/Controls/ActionPill.qml`, `qml/BackendStore.qml`) defines only these row actions: `Install`, `Retry`, `Upgrade`, `Downgrade`, `Reinstall`, `Uninstall`, `NoOp` (rendered "Installed", non-clickable), `NotAvailable`. `runRowAction()` has no Load/Launch case. An installed, matching package resolves to `NoOp` — terminal.
   - Evidence: `basecamp-load-evidence/details-panel-qml.txt`.

4. **Applications view does not expose local packages.** Welcome → Discover Applications → Installed returns `Nothing available for this platform / No configured repository publishes a build for linux-x86_64.`. Searching `registry` returns `No apps match your search. Try a different search term.`
   - Evidence: `basecamp-load-evidence/load-8-apps-installed.png`, `load-10-app-search-registry.png`.

5. **The module itself is a plain UI plugin.** Installed files: `Main.qml`, `libregistry_plugin.so`, `libregistry_ffi.so`, `manifest.json`, `manifest.sig`, `variant`, `.lgpm-source`. `Main.qml` is auto-generated by `spel-client-gen --target logos-module` and binds to an injected `backend` object; it is not self-launching.
   - Evidence: `basecamp-load-evidence/registry-qml-inspect.txt`.

## Exact blocker statement

RC2 Basecamp can **install** a local `.lgx` UI package and report it as installed with a verified hash, but provides **no mechanism to load or launch that UI module**. UI modules are loaded only by explicit shell actions (the bundled `package_manager_ui` is loaded when its welcome tile is clicked). A locally installed, standalone UI-only package has no launcher, no row action, and no repository catalog entry, so it never appears in the Applications view and is not loaded at startup.

This is a product/CLI gap in the RC2 AppImage, not a defect in the signed package: `lgx verify` still validates structure and signature, and the install hash matches the package.

## Reproduction

1. Launch only the isolated session:
   `setsid env -u WAYLAND_DISPLAY DISPLAY=:0 QT_QPA_PLATFORM=xcb QT_QUICK_BACKEND=software QSG_RHI_BACKEND=software LIBGL_ALWAYS_SOFTWARE=1 <AppImage> --user-dir /home/xps/logos-work/basecamp-test/session`
2. Welcome → Manage Packages → Tools → select `registry` → observe Details: Installed, hash above. No launch control.
3. Back → Discover Applications → Installed → observe empty platform result; search `registry` → no match.
4. Inspect `launch-load.log`: only `package_manager_ui` loaded.
5. Stop only that PID after verifying its command line contains the isolated `--user-dir`.
