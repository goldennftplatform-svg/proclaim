## On-chain program

`methods/guest/src/bin/registry.rs` exposes six instructions:

| Instruction | Purpose |
| --- | --- |
| `init_index` | One-time creation of the global registry index PDA. |
| `register` | Create an entry PDA keyed by the 32-byte program ID; append to index. |
| `update` | Mutate an existing entry; only the original author may call it. |
| `mark_verified` | Record an independent rebuild attestation (verifier + method + evidence CID). Self-verification is rejected. Changing `code_cid`/`commit`/`idl_cid`/`build_config` via `update` clears any prior attestation. |
| `lookup` | Read-only resolution by program ID. |
| `search` | Read the global index; clients derive entry PDAs and filter locally. |

### Account types

- `RegistryEntry` — program ID, name, version, author, description, tags,
  `idl_cid`, `code_cid`, commit, build config, timestamp, `deployer_claimed`,
  `source_verified`, `verifier`, `verification_method`, `evidence_cid`.
- `RegistryIndex` — `Vec<[u8; 32]>` of registered program IDs.

### Design notes

- **One PDA per program ID.** Seed is the program ID itself
  (`pda = arg("key")`), so lookup is deterministic and needs no indexer.
- **Logos Storage pointers.** `idl_cid` and `code_cid` point to the IDL document
  and source archive off-chain; the on-chain record is the signed pointer.
- **Source verification.** The rebuild happens off-chain, then `mark_verified`
  stores who verified, how, and where the evidence lives. A claim
  (`deployer_claimed`) is kept distinct from a verified rebuild, and the
  registering author cannot verify their own entry.
- **Search.** The on-chain primitive is the index PDA plus deterministic entry
  PDAs; tag/author/verified filtering is in `registry_core::search_entries`.

## Local workflow (no Docker)

This machine has no Docker, so guest builds use the local RISC Zero toolchain
and a small R0BF wrapper helper (`make-bin`, built from `risc0-binfmt` 3.0.5).

```bash
. ~/.cargo/env
export PATH="$HOME/.risc0/bin:$PATH"
export CARGO_BUILD_JOBS=2
export RUSTFLAGS='--cfg getrandom_backend="custom"'

cd ~/logos-work/registry
lgs build idl                       # regenerate registry-idl.json + generated clients
cargo test -p registry_core         # SDK tests
cargo +risc0 build --release \
  --manifest-path methods/guest/Cargo.toml \
  --target riscv32im-risc0-zkvm-elf
~/logos-work/make-bin/target/release/make-bin \
  methods/guest/target/riscv32im-risc0-zkvm-elf/release/registry \
  methods/guest/target/riscv32im-risc0-zkvm-elf/docker/registry.bin
lgs spel -- program-id methods/guest/target/riscv32im-risc0-zkvm-elf/docker/registry.bin --format hex
lgs wallet -- deploy-program methods/guest/target/riscv32im-risc0-zkvm-elf/docker/registry.bin
```

### CLI note

The PDA seed argument is `--key` — the spel CLI reserves `--program-id` as a
deprecated global flag. Signer accounts are named: `--author`, `--authority`,
`--verifier`.

```bash
AUTHOR=Public/HQk3STQocrbw16EhAMfSphd6fYrrnSdMHcG1KbfskDdh
VERIFIER=Public/CpSH8cuTUunA18SUEZ8Ky4SGbjQYW3ndJUbCLsigtuCN
PID=4df7d5396b68a16aae6d0f768ef447a0055eb43866827154f71139e486265144

lgs spel -- init-index --authority "$AUTHOR"
lgs spel -- register --key "$PID" \
  --name "LP-0023 Registry" --version "0.3.0" --description "..." \
  --tags "registry,spel,lez,search,verified" \
  --idl-cid <CID> --code-cid <CID> --commit <SHA> \
  --build-config "guest=local,risc0=3.0.5" --timestamp <UNIX_SECS> \
  --deployer-claimed true --author "$AUTHOR"

lgs spel -- pda entry --key "$PID"
lgs spel -- inspect <ENTRY_PDA> --type RegistryEntry
lgs spel -- pda index
lgs spel -- inspect <INDEX_PDA> --type RegistryIndex
lgs spel -- search
lgs spel -- mark-verified --key "$PID" \
  --method "reproducible-rebuild:program-id" \
  --evidence-cid <CID> --verifier "$VERIFIER"
```

## Independent rebuild verifier

`scripts/verify-source.sh` rebuilds the guest from source in a clean target
directory, wraps the ELF in R0BF, derives the program ID, and compares it with
the on-chain record. It was tested from a cold target directory (~3m20s) and
reproduced the deployed program ID exactly.

```bash
scripts/verify-source.sh <REGISTERED_PROGRAM_ID_HEX> [SOURCE_DIR] [EVIDENCE_CID]
```

On success it prints the ready-to-submit `mark-verified` command and an
`attestation.json` template.

## Logos Storage upload path (real CIDs)

The storage module runs (PID from `ps -ef | grep storage_module`) and exposes a
full upload API, but **not over HTTP**. It is a Qt Remote Objects (QtRO 2.0)
source on a Unix stream socket:

- Socket: `/tmp/logos_storage_module_<hash>` (also `/tmp/logos_storage_module_…`
  under `/tmp`; discover with `ss -xlp | grep logos_storage`).
- Wire format: QtRO/QDataStream handshake (`QtRO 2.0`, source `storage_module`,
  object `storage_module__handshake`), not JSON-RPC. A plain JSON probe gets the
  same binary handshake back.
- Relevant methods (from `strings storage_module_plugin.so`):
  - `uploadUrl(filePath: tstr, chunkSize: int, advertise: bool) -> sessionId`
    (async; completion CID arrives in the `storageUploadDone` event).
  - `uploadInit` / `uploadChunk` / `uploadFinalize` for streaming.
  - `manifests()`, `exists(cid)`, `fetch(cid, …)` for verification.
  - `importFiles(path)` uploads every file in a directory (headless helper).

To use from this machine you need a QtRO client (e.g. PySide6
`QtRemoteObjects.QRemoteObjectNode` with a dynamic replica, or a small C++ client
linked against `libQt6RemoteObjects.so.6` from the AppImage). None of Python
pip, PySide6, qmake, or Qt headers are installed here, so real uploads are
**blocked on setting up that client**; the CIDs in the on-chain record remain
placeholders until then. Once a client is available, upload the IDL JSON and a
source tarball, capture the two CIDs from `storageUploadDone`, then `update` the
entry and re-run `scripts/verify-source.sh` + `mark-verified`.
